# Лабораторийн ажил №5 — API систем тест: Postman ба Newman


**Оюутны нэр:** Оюунсүрэн Мөнхзолбоо  
**Оюутны код:** B210910878

## 1. Ажлын зорилго

Энэхүү лабораторийн ажлын зорилго нь REST API системийг Postman болон Newman ашиглан тестлэх, тест дизайны таван алхмыг бодит систем дээр хэрэгжүүлэх юм. Лабораторийн ажлын хүрээнд хичээлд бүртгүүлэх API-ийн амжилттай болон алдаатай нөхцөлүүдийг тодорхойлж, тэдгээрт тохирох тестүүдийг боловсруулсан. Postman ашиглан хүсэлтүүд болон шалгах нөхцөлүүдийг үүсгэж, Newman ашиглан командын мөрөөс автомат тест ажиллуулсан.

## 2. Ашигласан хэрэгслүүд

| Хэрэгсэл | Зориулалт |
|---|---|
| Node.js | API серверийг ажиллуулах |
| Postman | API хүсэлт болон тест боловсруулах |
| Newman | Postman collection-ийг автоматаар ажиллуулах |
| PowerShell | Команд ажиллуулах, үр дүн хадгалах |
| Git | Файлын өөрчлөлтийг удирдах |
| GitHub | Лабораторийн ажлыг хадгалах |

**Хувилбарын мэдээлэл:**

- Node.js: `node -v` — v24.19.0
- Newman: `newman.cmd -v` — 6.2.2

## 3. Тестлэгдэх функц

Энэ лабораторийн ажилд `POST /registrations` функцийг үндсэн тестлэгдэх функцээр сонгосон.

Тус функц нь оюутны мэдээлэл, хичээлийн мэдээлэл, оюутны идэвхтэй байдал болон урьдач нөхцөлийг шалгаж, бүртгэл хийх боломжтой эсэхийг шийдвэрлэдэг.

Ашигласан API endpoint-ууд:

| HTTP метод | Endpoint | Зориулалт |
|---|---|---|
| PUT | `/students/:id` | Оюутны мэдээлэл үүсгэх, шинэчлэх |
| PUT | `/courses/:id` | Хичээлийн мэдээлэл үүсгэх, шинэчлэх |
| POST | `/registrations` | Хичээлд бүртгүүлэх |
| GET | `/courses/:id` | Хичээлийн мэдээлэл харах |
| GET | `/registrations` | Бүртгэлийн мэдээлэл харах |

## 4. Тест дизайны сонголтууд

Тестлэгдэх функцийн оролт болон нөхцөлүүдийг дараах сонголтуудад хуваасан.

| № | Сонголт | Боломжит утгууд |
|---|---|---|
| 1 | Оюутны хүчинтэй байдал | Идэвхтэй, идэвхгүй, байхгүй |
| 2 | Оюутны үзсэн хичээл | Урьдач нөхцөлийг хангасан, хангаагүй |
| 3 | Хичээлийн хүчинтэй байдал | Байгаа, байхгүй |
| 4 | Хичээлийн урьдач нөхцөл | Бүгдийг үзсэн, огт үзээгүй, заримыг үзсэн, урьдач нөхцөлгүй |
| 5 | Хүсэлтийн өгөгдөл | Бүрэн, шаардлагатай талбар дутуу, JSON формат буруу |

## 6. Тестийн спецификаци

| № | Тестийн нөхцөл | Хүлээгдэх HTTP статус | Хүлээгдэх result |
|---|---|---|---|
| 1 | Идэвхтэй оюутан шаардлагатай хичээлийг үзсэн | 201 | OK |
| 2 | Оюутан системд байхгүй | 200 | ERROR_NO_STUDENT |
| 3 | Оюутан идэвхгүй | 200 | ERROR_INACTIVE_STUDENT |
| 4 | Хичээл системд байхгүй | 200 | ERROR_NO_COURSE |
| 5 | Оюутан урьдач нөхцөлийг хангаагүй | 200 | ERROR_PREREQUISITES |
| 6 | studentID талбар дутуу | 400 | ERROR_BAD_REQUEST |
| 7 | JSON формат буруу | 400 | ERROR_BAD_JSON |
| 8 | Урьдач нөхцөлгүй хичээлд бүртгүүлэх | 201 | OK |
| 9 | Оюутан болон хичээл хоёулаа байхгүй | 200 | ERROR_NO_STUDENT |

Нийт 9 тестийн нөхцөлийг боловсруулж, амжилттай бүртгэл, алдааны ангиуд, хязгаарын нөхцөл болон давхар алдааны хослолыг хамруулсан.

## 7. Postman тестийн хэрэгжүүлэлт

Postman дээр `Lab05 Registration API` нэртэй collection үүсгэсэн.

Collection-д тестийн нөхцөлүүдийг тусдаа бүлэг болгон зохион байгуулж, оюутан болон хичээлийн мэдээллийг бэлтгэх PUT хүсэлтүүд, бүртгэл шалгах POST хүсэлтүүдийг оруулсан.

Тестүүдэд HTTP статус болон JSON хариуны `result` талбарыг шалгах `pm.test()` oracle-уудыг ашигласан.

Амжилттай бүртгэлийн үед:

- HTTP статус 201 байх
- `result` нь `OK` байх

гэсэн хоёр нөхцөлийг шалгасан.

Бүртгэлийн дугаар нь сервер ажиллаж байх хугацаанд нэмэгддэг тул `registrationID`-ийн тогтмол утгыг шалгаагүй.

Үндсэн collection файл: `lab05-collection.json`

## 8. Давхар алдааны туршилт

Оюутан болон хичээл хоёулаа системд байхгүй үед ямар алдаа түрүүлж буцаж байгааг тодорхойлох зорилгоор давхар алдааны туршилт хийсэн.

Туршилтын үр дүнд HTTP статус 200 болон `ERROR_NO_STUDENT` хариу ирсэн.

Энэ үр дүнгээс оюутан болон хичээл хоёулаа байхгүй тухайн нөхцөлд оюутны хүчинтэй байдлын шалгалт түрүүлж хариу үүсгэж байгааг тогтоосон.

## 9. Newman автомат тестийн үр дүн

Postman collection-ийг Newman ашиглан командын мөрөөс ажиллуулж, PASS, FAIL, DOWN гэсэн гурван төрлийн туршилт хийсэн.

## 9.1 PASS туршилт

Үндсэн collection-ийн тестүүдийг API сервер ажиллаж байх үед гүйцэтгэсэн.

Collection: lab05-collection.json

Үр дүнгийн файл: results/newman-pass.txt

Iterations: 1

Requests: 19

Test scripts: 9

Assertions executed: 18

Assertions failed: 0

Exit code: 0

Үр дүн: PASS

Бүх assertion амжилттай шалгагдсан бөгөөд Newman exit code 0 буцаасан.

##9.2 FAIL туршилт

Тестийн шалгах нөхцөл (assertion)-ийг зориудаар буруу тохируулж, Newman алдааг илрүүлж байгаа эсэхийг шалгасан.

Collection: lab05-collection-fail.json

Үр дүнгийн файл: results/newman-fail.txt

Requests: 19

Test scripts: 9

Assertions executed: 18

Assertions failed: 2

Exit code: 1

Үр дүн: FAIL (зориуд үүсгэсэн)

Happy Path болон No Prerequisites хувилбаруудад HTTP 201 статусыг 200 гэж зориудаар хүлээсэн тул хоёр assertion амжилтгүй болсон. Энэ нь API-ийн алдаа биш, харин тестийн хүлээгдэж буй үр дүнг буруу тохируулснаас үүссэн алдаа юм.

	
FAIL туршилтад сервер ажиллаж байсан боловч тестийн хүлээгдэж буй үр дүн бодит хариутай зөрсөн. Харин DOWN туршилтад сервертэй холболт үүсээгүй. Иймээс FAIL нь oracle-ийн алдаа, DOWN нь холболтын буюу интерфейсийн алдаа юм.

## 10. Тест ажиллуулах заавар

Эхлээд API серверийг ажиллуулна.

node server.js

Дараа нь өөр терминалаас үндсэн collection-ийг ажиллуулна.

newman.cmd run lab05-collection.json 

FAIL туршилтыг ажиллуулах:

newman.cmd run lab05-collection-fail.json 

DOWN туршилтын үед API серверийг зогсоож, үндсэн collection-ийг дахин ажиллуулна.

## 12. Дүгнэлт

Энэхүү лабораторийн ажлаар REST API системийг Postman болон Newman ашиглан тестэлж сурсан. Тест дизайны таван алхмаас сонголтуудыг тодорхойлох болон тэдгээрийн төлөөлөх утгыг сонгох хэсэг хамгийн их бодол шаардсан. Учир нь оюутны идэвхтэй байдал, хичээлийн хүчинтэй байдал болон урьдач нөхцөлийн олон төрлийн хослолыг авч үзэх шаардлагатай болсон. Зарим хослолд өмнөх шалгалтаар алдаа буцдаг тул дараагийн нөхцөлийг тусад нь ажиглах боломжгүй байгааг ойлгосон. Оюутан болон хичээл хоёулаа байхгүй үед ERROR_NO_STUDENT хариу буцаж байгааг туршилтаар тогтоосон. Үндсэн collection-ийн 18 assertion бүгд амжилттай болсон тул шалгасан нөхцөлүүдэд API-ийн батлагдсан согог илрээгүй. Харин FAIL туршилтаар зориуд буруу oracle ашиглахад Newman хоёр assertion-ийн алдааг илрүүлсэн. DOWN туршилтаар сервер ажиллахгүй үед холболтын алдаа үүсдэг бөгөөд энэ нь oracle-ийн алдаанаас ялгаатай болохыг харуулсан. Энэ ажлаар тестийн үр дүнг автоматжуулж, exit code ашиглан амжилттай болон амжилтгүй гүйцэтгэлийг ялгах дадлага эзэмшсэн.
